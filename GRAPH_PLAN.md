# План построения графа навигации

## Идея
Вместо реактивной навигации (реагировать на препятствия) использовать **заранее известный граф узлов** для статичной карты.

## Преимущества подхода
✅ **Надёжность**: робот знает куда ехать, не теряется
✅ **Предсказуемость**: одинаковый маршрут при каждом запуске
✅ **Простота отладки**: проблемы видны на графе
✅ **Точность**: движение к конкретным координатам

## Структура графа (пример)

```
START (0.0, 0.0, 0°)
   ↓
EXIT_POCKET (-1.8, 0.2, 180°)  ← выехал из кармана на юг
   ↓
TURN_EAST (-1.8, 0.2, -90°)    ← повернулся на восток
   ↓
BEFORE_PALLETS (-1.2, 0.2, -90°)  ← перед паллетами
   ↓
[выбор пути]
   ├─→ THROUGH_GAP (0.0, 0.2, -90°)      ← через узкий проход
   └─→ AROUND_NORTH (0.0, 1.5, -45°)     ← обход с севера
   ↓
CORRIDOR_ENTRANCE (2.0, 0.2, -90°)
   ↓
... и так далее
```

### Фаза 4: Идея "подруливания издалека"
Если следующий узел за препятствием, но робот видит его на лидаре:
```python
# Вместо слепого движения к цели
move_to_node(target_x, target_y)  # может врезаться

# Подруливание по данным лидара
while distance_to_target > 0.5:
    gap = find_gap_towards_target(lidar_data, target_angle)
    if gap:
        turn_towards_gap(gap.angle)
        move_forward(0.2)
    else:
        # Препятствие, не можем проехать
        fallback_to_avoid_obstacle()
```

## Пример узлов для лабиринта

### Комната 1 (карман с утками)
- `START` - стартовая позиция
- `TURNED_SOUTH` - развернулись на юг
- `AT_SOUTH_WALL` - у южной стены
- `TURNED_EAST` - повернулись на восток

### Между паллетами
- `BEFORE_PALLETS` - перед паллетами
- `GAP_SOUTH` - узкий проход у южной стены (основной путь)
- `GAP_NORTH` - обход с севера (запасной)
- `AFTER_PALLETS` - после паллет

### Коридор
- `CORRIDOR_ENTRANCE` - вход в коридор
- `CORRIDOR_MID` - середина коридора
- `CORRIDOR_EXIT` - выход во 2 комнату

### Комната 2
- `ROOM2_ENTRANCE` - вошли во 2 комнату
- `ROOM2_EAST` - двигаемся на восток
- `FINISH_APPROACH` - подъезд к финишу
- `FINISH` - финиш!
